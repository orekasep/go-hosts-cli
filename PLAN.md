# hostcli: Architecture, Design & Implementation Plan

> **`hostcli`** is a modern, cross-platform `/etc/hosts` manager built with Go, offering an interactive [Bubble Tea](https://github.com/charmbracelet/bubbletea) Terminal User Interface (TUI), a scriptable Command Line Interface (CLI), safe atomic application, one-click rollback, and cross-platform migration for macOS, Linux, and Windows.

## 1. Core Principles & Zero-Data-Loss Architecture

`hostcli` avoids configuration corruption and lost edits via a strict **two-tier persistence model**:

```
[ User edits in TUI or CLI ]
              │
              ▼ (Instant, unprivileged write)
┌──────────────────────────────────────────────┐
│  Tier 1: ~/.hostcli/hosts.yaml (User Home)   │  <-- Edits are ALWAYS saved here immediately.
└──────────────────────────────────────────────┘      Zero data loss even if sudo fails.
              │
              ▼ (Requires Sudo / Admin privilege)
┌──────────────────────────────────────────────┐
│  Tier 2: /etc/hosts or drivers/etc/hosts     │  <-- Updated ONLY when Apply is explicitly invoked.
└──────────────────────────────────────────────┘
```

### Key Pillars
- **Decoupled State**: Edits live in the user's home folder (`~/.hostcli/hosts.yaml`). They never touch system files until explicitly applied.
- **Deterministic Boundary Markers**: All `hostcli`-managed entries in `/etc/hosts` are strictly enclosed between `# BEGIN HOSTCLI` and `# END HOSTCLI`. System entries (preamble) and un-managed custom lines (suffix) are preserved byte-for-byte.
- **Fail-Safe Rollback**: Reverting changes can be done instantly either by stripping the managed block or restoring the pristine pre-migration backup (`hosts.original.bak`).

## 2. Cross-Platform Paths & Migration Engine

### Dynamic Path Resolution

| Platform | System Hosts Path | User Config Path (`USER_HOME`) |
|---|---|---|
| **macOS** | `/etc/hosts` | `~/.hostcli/hosts.yaml` |
| **Linux** | `/etc/hosts` | `~/.hostcli/hosts.yaml` |
| **Windows** | `%SystemRoot%\System32\drivers\etc\hosts` (`C:\Windows\System32\drivers\etc\hosts`) | `%USERPROFILE%\.hostcli\hosts.yaml` |

### Import & Migration Strategy (`hostcli import`)

1. **Automatic Backup**: On initial import, copies the raw system hosts file to `~/.hostcli/backups/hosts.original.bak`.
2. **Parser Heuristics**:
   - Standard loopback/local entries (`127.0.0.1 localhost`, `::1 localhost`, etc.) are grouped under a protected `system` group.
   - Section headers (e.g., `# Dev Servers`, `## Kubernetes`) are parsed into distinct group hierarchies (e.g., `dev`, `kubernetes`).
   - Inline comments and secondary hostnames are split into `aliases` and `comment`.
3. **Structured YAML Schema**:

```yaml
version: 1
groups:
  - name: system
    entries:
      - id: 01HQX100000000000000000001
        ip: 127.0.0.1
        hostname: localhost
        aliases: []
        enabled: true
        comment: "Default loopback"
      - id: 01HQX100000000000000000002
        ip: "::1"
        hostname: localhost
        aliases: []
        enabled: true
        comment: "IPv6 loopback"
  - name: work/dev
    entries:
      - id: 01HQX200000000000000000001
        ip: 192.168.1.50
        hostname: api.dev.local
        aliases: ["api", "gateway"]
        enabled: true
        comment: "API Gateway microservice"
```

## 3. Safe Apply, Atomic Writes & Rollback Engine

### Managed Block Format

```hosts
127.0.0.1 localhost
::1       localhost

# BEGIN HOSTCLI
# Generated by hostcli. Do not edit this block manually.
192.168.1.50   api.dev.local gateway   # [work/dev] API Gateway microservice
# END HOSTCLI

# Any user-defined entries outside the block remain untouched
```

### Safety Guarantees During Write
1. **Refuse Symlinks**: Reads and checks targets with `os.Lstat` to prevent symlink-following attacks.
2. **Same-Filesystem Temp File**: Temporary files (`.hostcli-tmp-*`) are created in the target directory (e.g. `/etc/` or `System32\drivers\etc\`) ensuring `os.Rename` is an atomic inode swap without cross-device errors (`EXDEV`).
3. **Strict Permissions**: Clamps mode to `0644` (stripping SUID, SGID, and world-writable bits).
4. **Signal Cleanup**: Intercepts `SIGINT` and `SIGTERM` via goroutine signal listener to unlink temp files on interruption.

### Rollback Mechanisms
- **Block Strip Rollback (`hostcli rollback`)**: Extracts the content before `# BEGIN HOSTCLI` and after `# END HOSTCLI`, removing all `hostcli` entries cleanly without resetting custom third-party hosts.
- **Pristine Snapshot Rollback (`hostcli rollback --original`)**: Restores the verified `hosts.original.bak` taken during the first migration.
- **Timestamped Snapshots**: Every successful apply creates an automatic snapshot in `~/.hostcli/backups/hosts_<timestamp>.bak`.

### Automatic DNS Cache Flush
- **macOS**: `dscacheutil -flushcache && killall -HUP mDNSResponder`
- **Linux**: `resolvectl flush-caches` (systemd-resolved) or `systemctl restart nscd`
- **Windows**: `ipconfig /flushdns`

## 4. Startup Privilege Detection & Sudo/UAC Handoff

### Pre-Flight Privilege Check

On app startup, `hostcli` tests direct write capability on the system hosts file:
1. **If Writable (Root / Elevated Admin)**: Operates seamlessly without escalation prompts.
2. **If Non-Writable (Standard User)**:
   - Sets runtime state: `PrivilegeLevel = Unprivileged`.
   - Checks presence of `sudo` (macOS/Linux) or elevated tokens (Windows).
   - Shows a prominent status indicator in the UI:
     `[🔒 Unprivileged: changes saved to ~/.hostcli; sudo requested on Apply]`
   - Displays an informational startup banner explaining that edits are safely saved locally and sudo is only required when pushing to `/etc/hosts`.

### TUI Sudo Handoff via `tea.ExecProcess`

When pressing **`A`** (Apply) or **`R`** (Rollback) in Bubble Tea:
```go
func runPrivilegedApplyCmd() tea.Cmd {
    c := exec.Command("sudo", os.Args[0], "apply")
    c.Stdin = os.Stdin
    c.Stdout = os.Stdout
    c.Stderr = os.Stderr
    return tea.ExecProcess(c, func(err error) tea.Msg {
        return applyFinishedMsg{err: err}
    })
}
```
- Bubble Tea suspends terminal raw mode and lets `sudo` handle the password prompt directly in the terminal.
- When `sudo` completes (or fails), Bubble Tea regains terminal control and resumes the interface without crashing or losing any state.

### Left Sidebar Components
1. **Group Hierarchy**: Lists groups (`[All]`, `system`, `work/dev`, `personal`) with active entry counters.
2. **Quick Actions Cheatsheet**: Visual shortcuts for common operations (`a`, `e`, `d`, `Space`, `/`).
3. **System Sync Panel**: Action shortcuts for `[A] Apply`, `[R] Rollback`, and `[m] Migrate`.

### Right Area Components
1. **Entries Table**: Columns for `STATUS` (`● ON` / `○ OFF`), `IP ADDRESS`, `HOSTNAME`, `ALIASES`, and `COMMENT`.
2. **Unsaved Edits Indicator**: Modified or unapplied rows display a subtle yellow indicator.

### Interactive Modals (Overlay)
- **Add / Edit Modal**: Form inputs for IP address (with instant syntax validation), Hostname, Aliases, Group selector, and Comment.
- **Confirm Deletion / Rollback Modal**: Safeguards destructive actions with explicit `y/n` confirmation.
- **Fuzzy Search Modal**: Uses `sahilm/fuzzy` across hostnames, aliases, IPs, and groups.

## 6. CLI Command Reference

| Command | Arguments | Flags | Description |
|---|---|---|---|
| `hostcli` | - | - | Launches interactive Bubble Tea TUI |
| `hostcli import` | - | `--from <path>` | Migrates system hosts file to `~/.hostcli/hosts.yaml` |
| `hostcli apply` | - | `--dry-run` | Writes enabled entries to system hosts inside managed block |
| `hostcli rollback` | - | `--original`, `--dry-run` | Reverts system hosts (strips block or restores `.orig`) |
| `hostcli list` | - | `--json`, `--yaml`, `--group` | Displays configured entries |
| `hostcli diff` | - | - | Prints unified diff between system hosts and configuration |
| `hostcli add` | `<ip> <hostname>` | `--group`, `--alias`, `--comment` | Adds a new entry |
| `hostcli rm` | `<hostname>` | `--force` | Deletes an entry |
| `hostcli enable` | `<hostname>` | - | Enables an entry |
| `hostcli disable` | `<hostname>` | - | Disables an entry |
| `hostcli completion`| `<shell>` | - | Generates auto-completion (bash, zsh, fish, pwsh) |

## 7. Distribution, Packaging & Releases

### Release Automation via GoReleaser & GitHub Actions

On `git push origin v*`:
1. **GitHub Actions** triggers `.github/workflows/release.yml`.
2. **GoReleaser**:
   - Cross-compiles binaries for `darwin/amd64`, `darwin/arm64`, `linux/amd64`, `linux/arm64`, `windows/amd64`, `windows/arm64`.
   - Generates `checksums.txt` and GitHub Release notes.
   - Pushes updated Homebrew Formula to `homebrew-tap` repository.
3. **Chocolatey Job** (Windows runner):
   - Injects the version and checksum into `hostcli.nuspec` and `chocolateyinstall.ps1`.
   - Packages `.nupkg` and pushes to `push.chocolatey.org`.

### Installation Methods

```bash
# --- macOS / Linux (Homebrew) ---
brew tap <username>/tap
brew install hostcli

# --- Windows (Chocolatey) ---
choco install hostcli

# --- Go Install ---
go install github.com/<username>/hostcli/cmd/hostcli@latest
```

```

├── .github/workflows/
│   └── release.yml                 # Automated release pipeline

│           ├── chocolateyinstall.ps1
│           └── chocolateyuninstall.ps1
├── cmd/
│   └── hostcli/
│       └── main.go                 # App entrypoint
├── internal/
│   ├── domain/                     # Entities & IP/host validators
│   ├── core/
│   │   ├── config/                 # YAML serializer/deserializer
│   │   ├── etchosts/               # Marker block parser, atomic writer
│   │   ├── backup/                 # Snapshot backup and restore
│   │   ├── migrate/                # Parser for importing existing hosts files
│   │   └── render/                 # Formats entries into hosts block
│   ├── apply/

│   └── tui/                        # Bubble Tea UI components & models

└── go.sum
```

### Execution Steps
1. **Phase 1: Domain & Core Engine**: Models, YAML persistence, marker parser, atomic writer, backup/rollback, and migration parser.
2. **Phase 2: CLI Subcommands**: Cobra commands (`import`, `apply`, `rollback`, `list`, `add`, `rm`, `enable`, `disable`, `diff`).
3. **Phase 3: Bubble Tea TUI**: Sidebar navigation, entries table, quick actions, modals, and sudo handoff.
4. **Phase 4: Packaging & CI/CD**: GoReleaser config, Chocolatey package scripts, and GitHub Actions workflow.
5. **Phase 5: Automated Testing**: Unit tests for parser, marker extraction, atomic replacement, and cross-platform path resolution.
